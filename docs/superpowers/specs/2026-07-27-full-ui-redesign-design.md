# 美团试新 Demo 全站 UI 精修规格

日期：2026-07-27  
状态：已确认，待实施  
范围：消费者端、订单闭环、个人中心、商家端  

## 1. 目标与边界

本轮只优化 UI、页面展示结构与交互反馈，不新增业务功能，不修改数据库口径，不改变已跑通的页面流程。

目标是把当前可运行 MVP 精修成可以提交比赛的完整 Demo：第一眼像美团正式业务，第二眼能理解“可信证据”这一创新机制。

明确不做：

- 注册、登录与多用户权限
- 公网部署
- 积分商城
- 附近想吃社区
- 完整平台申诉系统
- 美团真实接口
- 新业务页面

## 2. 视觉方向

采用“美团原生升级版”。

### 2.1 视觉关键词

- 可信
- 克制
- 真实消费
- 清晰决策
- 美团原生

### 2.2 色彩

- 美团黄：主按钮、选中状态、关键成长进度
- 暖白：消费者端主背景
- 浅灰白：商家经营后台背景
- 深黑：标题、顶部导航和核心数据
- 可信绿：稳定兑现与正向状态
- 琥珀色：证据成长、样本不足和一般提醒
- 风险红：争议、明确失败和高风险状态

禁止使用浏览器默认蓝色链接。避免大面积黄色、过度渐变和无意义装饰色。

### 2.3 字体与信息层级

- 全站使用清晰的现代中文无衬线字体组合
- 页面只保留一个最高级标题
- 取消宋体、海报字、夸张断行和大段口号式文案
- 关键决策信息不小于 16px
- 正文不小于 14px
- 辅助信息可以使用 12–13px，但必须保持可读对比度

### 2.4 卡片与容器

- 控件圆角：8–10px
- 普通卡片圆角：12–16px
- 重点容器圆角：18–20px
- 卡片使用细边框和轻阴影
- 删除斜角、虚线装饰框、硬黑投影、印章式装饰和无意义网格纹理
- 卡片只用于店铺、商品、订单、承诺和指标等独立业务实体

### 2.5 图片

- 店铺与商品优先使用真实餐品图片
- 图片风格统一为自然光、近景、真实外卖消费场景
- 缺少图片时使用统一品类插画占位，不使用单个汉字作为长期正式图片
- 图片需要提供稳定尺寸，避免加载时页面跳动

### 2.6 动效

只保留四类必要动效：

1. 页面进入
2. 筛选切换
3. 下单成功
4. 证据数字成长

所有动效支持减少动态效果设置，不使用持续漂浮或纯装饰动画。

## 3. 消费者端

### 3.1 试新首页

页面顺序：

1. 顶部品牌与搜索
2. 附近正在试新的店铺标题
3. 时段、品类和决策筛选
4. 店铺列表
5. 底部导航

设计要求：

- 缩短深色首屏高度，搜索框成为唯一主操作
- 示例需求作为快捷填入，不与筛选入口争夺层级
- 时段、品类、价格和排序统一在一个紧凑筛选面板内
- 筛选支持组合，选中状态明确
- “高兑现新店”不作为重复入口，只作为排序结果或店铺状态
- 列表底部预留安全距离，固定导航不得遮挡内容

### 3.2 店铺卡片

每张卡片只保留：

- 真实餐品图
- 店名和主推商品
- 起售价格或试新套餐价格
- 距离、预计送达时间、人均
- 一项核心证据
- 一项风险或可信状态
- 清晰的进入店铺操作

统一状态：

- 可信稳定
- 证据成长中
- 存在待核验

每张卡片必须有差异化决策理由，避免所有卡片只更换店名和数字。

### 3.3 店铺详情

信息结构：

1. 店铺头部
2. 点菜 / 证据 / 商家标签
3. 本店可锁定承诺
4. 商品列表
5. 购物车与结算操作

点菜页直接展示用户需要知道的承诺、兑现率、样本量和风险。消费者不需要进入商家后台理解承诺。

删除抽象文案，例如“这家店的取舍”“不让一句好评说了算”。统一使用消费语言：

- 本店可锁定的承诺
- 真实订单验证
- 已兑现
- 符合预期
- 样本较少
- 待核验

### 3.4 证据页

只回答：

1. 有多少笔完成订单参与验证
2. 哪些承诺得到兑现
3. 目前仍有什么不确定性

页面包含：

- 有效验证总数
- 客观承诺兑现率
- 主观感受分布
- 正常价复购意愿
- 一条反向记录或待核验状态
- 可展开的结构化验证记录

不展示自由文本评论。

## 4. 订单闭环

### 4.1 结算页

视觉顺序：

1. 商品与数量
2. 配送及价格信息
3. 本单锁定承诺
4. 承诺版本和商家确认时间
5. 提交模拟订单

主按钮保持固定、明确，不被说明文字抢夺层级。

### 4.2 订单详情

- 使用清晰时间轴展示已创建、制作中、配送中、待验证、已完成和争议中
- Demo 推进工具收纳到边缘控制器，不进入正常订单内容
- 当前状态和下一步操作必须在首屏可见

### 4.3 餐后验证

- 使用轻量问题卡，不做成长问卷
- 客观承诺逐项对应订单快照
- 主观感受和复购意愿独立采集
- 无法判断可以跳过
- 选择未兑现时展开图片与核验入口
- 正向验证和负向反馈使用中性文案，不诱导好评

### 4.4 证据成长

- 只突出一次关键变化，例如有效验证 8 → 9
- 次级指标使用简洁列表展示
- 提供返回订单、查看更新后店铺证据或进入商家经营台的明确操作

## 5. “我的”

采用美团订单中心心智。

顶部状态：

- 待验证
- 进行中
- 已完成
- 争议中

下方展示：

- 真实订单列表
- 每个订单当前状态
- 验证入口或验证结果
- 我的有效验证数

不保留无内容、不可点击或与首页重复的入口。

## 6. 商家端

### 6.1 总体风格

- 使用浅灰白桌面经营后台
- 通过宽布局、深色导航和数据密度区分消费者端
- 沿用美团黄主操作、可信绿状态与相同基础组件
- 不使用纯文本堆叠作为页面主体

### 6.2 经营总览

首屏顺序：

1. 店铺身份与试新状态
2. 关键经营指标
3. 可信成长进度
4. 当前承诺
5. AI 经营建议
6. 最近验证

指标必须独立分块：

- 有效验证数
- 客观承诺兑现率
- 主观感受符合率
- 正常价复购意愿
- 今日新增
- 待核验数量

### 6.3 承诺方案

使用标准流程步骤：

1. 选择商品
2. AI 提取候选承诺
3. 商家确认、修改或拒绝
4. 设置试新名额
5. 预览
6. 发布

当前步骤、已完成步骤和未开始步骤需要有明显差异。发布后应能在消费者端店铺页看到新承诺。

### 6.4 订单核验与证据分析

- 待核验反馈必须展示订单、承诺项、结构化结果和处理状态
- 证据分析区分客观兑现、主观感受和复购意愿
- AI 建议必须说明依据，不能只给一句泛化结论

## 7. 全站交互与响应式

- 所有可点击元素必须具备悬停、按下、选中、展开、Toast、跳转或数据刷新反馈
- 手机端触控区域不小于 44 × 44px
- 键盘焦点清晰可见
- 底部固定导航不遮挡列表和按钮
- 支持 320px 以上手机宽度、平板及桌面演示尺寸
- 长文本、空状态、加载状态和接口失败状态保持可读
- 使用语义化按钮和链接，不允许伪按钮

## 8. 实施范围

允许修改：

- CSS Token
- 全局字体与背景
- 基础按钮、卡片、标签和抽屉样式
- 页面布局与展示顺序
- 图片资源和图片占位方式
- 动效与响应式样式
- 为了视觉语义所需的少量展示组件拆分

禁止修改：

- API 口径
- 数据库结构
- 推荐逻辑
- 订单状态机
- 验证计算
- 路由含义
- 已确认业务流程

## 9. 验收标准

1. 首页 10 秒内能理解“试新帮助用户用真实证据选择新店”
2. 所有页面视觉上属于同一套产品
3. 消费者端像正式美团频道，不像说明书或路演 PPT
4. 商家端像经营后台，不像纯文本报告
5. 核心状态在不阅读长文案的情况下可以识别
6. 店铺卡片能快速比较，不需要逐字阅读
7. 手机和桌面端均无明显遮挡、溢出或不可点击元素
8. 原有业务测试全部通过
9. 新增关键视觉结构测试，防止后续回退
10. 不引入新功能和新业务口径
